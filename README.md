# genetico.in

The website for **Genetico**, a health technology company building digital infrastructure for rare
and genetic disease care. Its platform is **IndiGeneUs.AI**.

- **Next.js 16** (App Router) + **React 19** + **Tailwind CSS 4**, TypeScript throughout.
- **Payload CMS 3**, embedded in the same app at `/admin`, on **Supabase** Postgres and Storage.
- **Resend** delivers the enquiry form. **Google Tag Manager** loads analytics behind a cookie banner.
- Deployed on **Vercel** from `main`.

Editors: see **[CMS.md](CMS.md)** — how to change anything on the site from `/admin`.
Contributors: see **[CONTRIBUTING.md](CONTRIBUTING.md)** — branching, commits and checks.

## Getting started

Node 20.11+ (22 pinned in `.nvmrc`).

```bash
npm install
cp .env.example .env     # fill in the values — see below
npm run dev              # http://localhost:3000, admin at /admin
```

> **`.env` points at the production database.** There is no staging database, so anything you
> change in `/admin` locally — or any script you run — changes the live site's content. Take a
> backup (`npm run cms:backup`) before any schema or data work.

### Environment

| Variable                 | Purpose                                                                                        |
| ------------------------ | ---------------------------------------------------------------------------------------------- |
| `PAYLOAD_SECRET`         | Signs admin sessions. 32+ characters.                                                          |
| `DATABASE_URI`           | Supabase Postgres connection string.                                                           |
| `S3_*`                   | Supabase Storage, for images uploaded in the CMS.                                              |
| `RESEND_API_KEY`         | A Resend key allowed to send.                                                                  |
| `RESEND_FROM`            | Sender, on a domain verified in Resend — e.g. `Genetico Website <website@indigeneus.ai>`.      |
| `RESEND_TO`, `RESEND_CC` | Fallback recipients. The CMS (Site-wide → Contact details & form) decides where enquiries go.  |
| `NEXT_PUBLIC_SITE_URL`   | Optional. The canonical origin; defaults to `https://genetico.in`.                             |
| `NEXT_PUBLIC_GTM_ID`     | Optional. The Tag Manager container; defaults to `GTM-MHNFM4ZM`. Set to empty to turn GTM off. |

Without `DATABASE_URI` the site still builds and renders from its built-in copy, which is what keeps
CI green without production credentials.

### Commands

| Command                                       | What it does                                                    |
| --------------------------------------------- | --------------------------------------------------------------- |
| `npm run dev`                                 | The site and the admin panel, with hot reload.                  |
| `npm run build` / `npm start`                 | Production build / serve it.                                    |
| `npm run lint` / `typecheck` / `format:check` | The checks CI runs on every PR.                                 |
| `npm run generate:types`                      | Regenerate `src/payload-types.ts` after changing any CMS field. |
| `npm run cms:backup`                          | Dump every CMS table to `.cms-backup/` (gitignored). Read-only. |
| `npx tsx scripts/print-admin-nav.mts`         | Print the admin sidebar as an editor sees it.                   |

Database scripts are described in **[scripts/README.md](scripts/README.md)**.

## How the code is organised

```
src/
  app/
    (site)/            the public website — one folder per page, plus its root layout
    (payload)/         the /admin panel and Payload's API (generated by Payload; do not edit)
    api/contact/       POST endpoint for the enquiry form
    sitemap.ts, robots.ts, manifest.ts, global-not-found.tsx
  components/
    chrome/            what every page shares: header, section rail, footer, enquiry form, cookie banner
    home/ about/ platform/ hospital/ life-science/ public-health/ resources/ solutions/ blog/ legal/
                       one folder per page's sections
    motion/            small animation helpers
  content/             each page's built-in copy, and the illustrative demo data in the product mock-ups
  lib/
    cms/               loaders that read the CMS and fill gaps from content/ (one per page)
    routes.ts          every public path — import these rather than typing paths
    seo.ts, seo-pages.ts   canonical URL, metadata, structured data, per-page titles
    analytics.ts       Tag Manager and Consent Mode
  payload/             the CMS schema: collections/, globals/sections/ (one file per page), admin/
  payload.config.ts
  proxy.ts             redirects CMS media requests straight to Supabase Storage
  archive/             earlier design previews — kept for reference, not built or routed
scripts/               database tools; scripts/migrations/ holds ones already applied
design_handoff_genetico_site/   the designer's HTML prototypes for each page (reference only)
```

### How a page gets its content

1. A page in `src/app/(site)/` calls its loader, e.g. `getHomePage()` in `src/lib/cms/home-page.ts`.
2. The loader reads that page's sections from Payload (`getSectionGlobal()` in `lib/cms/queries.ts`).
3. `withDefaults()` lays each section over the page's built-in copy in `src/content/`: a field left
   empty in the CMS shows the built-in text, so a page never renders a hole — and renders in full
   even if the database is unreachable.
4. The page passes each section its copy as props.

Pages are statically rendered and revalidate every 60 seconds; saving in `/admin` revalidates them
immediately (`src/payload/hooks/revalidate-site.ts`).

### Changing the CMS schema

Payload pushes schema changes straight to the database the next time `npm run dev` starts.

- **Adding** a field or section is safe.
- **Removing or renaming** one makes the dev server stop on an interactive "delete this column?"
  prompt (and a wrong answer loses data). Instead: back up, write the SQL as a script in `scripts/`
  (transactional, idempotent, with `--dry`), run it, _then_ remove the field and start the server.
  `scripts/drop-retired-cms-tables.mjs` is the pattern.

After any schema change run `npm run generate:types`, and keep `src/payload/admin/nav-order.ts`, the
section's numbered label, and the matching `src/content/` object in step. Conventions that keep the
admin usable for a non-technical editor are in `src/payload/fields/copy.ts` and CMS.md.

### Design system

Tokens (colours, type, spacing, breakpoints `nav` = 880px and `mid` = 1040px) are defined in
`src/app/globals.css` under `@theme`. Fonts: Newsreader (headlines), DM Sans (body), IBM Plex Mono
(labels). The pages still on the earlier design — blog, legal pages, coming-soon — use Albert Sans.

Put width-dependent styles on the element as Tailwind variants (`mid:grid-cols-2`) rather than as
media queries appended to `globals.css`.

## SEO, analytics and compliance

- **Canonical domain** is `https://genetico.in` (`src/lib/seo.ts`). Every canonical tag, Open Graph
  URL, the sitemap and robots.txt use it, whichever host served the page.
- **`/sitemap.xml`** lists every public page and blog post. **`/robots.txt`** allows everything
  public, points at the sitemap, and on any non-production deploy disallows everything.
- **Design previews** (`/home-v2`, `/home-v3`, `/home-v4`, `/about-v2`) are archived in
  `src/archive/` and redirect (308) to the live page they drafted.
- **Tag Manager** loads in `<head>` of the public site only — never in `/admin`. Google Consent
  Mode v2 defaults analytics and ad storage to _denied_ until the visitor accepts in the cookie
  banner (`src/components/chrome/cookie-consent.tsx`); the choice is remembered and can be changed
  from "Cookie settings" in the footer. Tags inside the container must respect consent (GA4 does).
- **Legal pages**: `/privacy-policy` and `/cookie-policy`, edited in the CMS.

## Deployment

Vercel builds and deploys `main`. Set the environment variables above in the Vercel project, add
`genetico.in` as the production domain, and redirect `www.genetico.in` (and the `*.vercel.app`
alias) to it so there is one canonical host.
